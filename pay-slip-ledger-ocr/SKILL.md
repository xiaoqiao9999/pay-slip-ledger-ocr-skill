# 付款回单 OCR 台账

## Overview

将财务发来的付款回单图片批量 OCR 识别，提取 12 个字段追加写入 Excel 台账，
并把识别成功的原图按「收款人名称_金额两位小数_摘要[_记账日期].png」重命名、
归入 `已完成/<收款人名称>/` 供应商子文件夹。增量式、幂等去重，可反复运行。

核心资产：`scripts/pay_slip_ledger_scan.py`（主脚本，含全部正则与台账逻辑）；
详细规则见 `references/ledger-spec.md`；OCR 引擎与跨机部署见
`references/ocr-engine.md`；供用户阅读的图文说明在 `assets/付款回单台账_使用说明.html`。

## 前置条件

1. 本机已装 `openpyxl`（`python -m pip install openpyxl`）
2. OCR 引擎可用（`references/ocr-engine.md` 第 1 节探测逻辑；本机默认已就位）
3. 工作区含 `输入/` 投放目录（脚本以自身所在目录为工作区，或传参覆盖）

## 执行流程

### Step 1 — 确认投放与台账现状

- 列出 `输入/` 目录图片数量与文件名；读取现有台账行数与合计金额。
- 若 `输入/` 为空 → 告知用户无待处理图片，结束（不空跑 OCR）。

### Step 2 — 运行主脚本（默认正式模式）

```bash
python scripts/pay_slip_ledger_scan.py
```

- 工作区 = 脚本所在目录（本技能目录或复制到的工作区目录）。
- 指向既有业务工作区时用显式参数：
  `python <工作区>/pay_slip_ledger_scan.py --input <工作区>/输入 --output <工作区>/付款回单台账.xlsx --done <工作区>/已完成`
- 图片量大（>15 张）时后台运行，单张约 20 秒。

其他参数：`--dry-run` 只预览不写盘；`--limit N` 只处理前 N 张；
`--ocr-script <path>` 覆盖 OCR 引擎路径。

### Step 3 — 校验产物

- 台账：数据行数 = 原行数 + 新增；合计行金额 = 各数据行 Decimal 之和。
- `输入/` 清空（完整识别时）、`已完成/` 按收款人出现新子文件夹、命名符合规范
  （金额两位小数、日期段可省略）。
- 结果分四类核对：完整归档 / 待人工核对（必须项缺失）/ OCR 失败 / 重复跳过。

### Step 4 — 处理异常与汇报

- **待人工核对**：必须项（收款人/金额/摘要）缺失的行 → 留在 `输入/`，
  向用户报告文件名与缺哪些字段，请其补图或人工处理。
- **OCR 失败**：偶发重跑一次；持续失败检查图片是否为回单、朝向是否正常。
- **半截回单**（只有上半部分、缺底部日期/流水号/批次号）：三项必须字段齐全
  即正常入账+归档，不要拦截（详见 ledger-spec 第 5 节）。
- **重复投放**：去重键为会计流水号，已在台账则自动跳过——直接说明即可。
- 完成后向用户汇报：新增/归档/跳过/待核对各几张，台账新行数与合计金额。

## 规则速查（详见 references/ledger-spec.md）

- **台账 12 列**：序号/记账日期/付款人名称/收款人名称/收款人账号/开户行/币种/
  金额/金额大写/摘要/会计流水号/批次元号
- **必须项**：收款人名称、金额、摘要；其余可选、缺失留空
- **归档命名**：`收款人_金额两位小数_摘要[_日期].png` → `已完成/<收款人>/`，重名 `_2`
- **去重**：按会计流水号；合计行用 Decimal 求和，追加与合计单次读写
- **开户行取第二个**「开户行名称」（收款方）
- **不自动归并**供应商名称变体；人工合并需文件+台账+空文件夹三处同步

## 维护提示

- 脚本为正则驱动、表头 table-driven：加字段 = FIELDS 字典加一行 + HEADERS 加一列。
- 若本技能发现新 OCR 变体或规则变更，更新 `references/ledger-spec.md` 并同步主脚本。
